## §2. 공통 규칙 (모든 보고서에 예외 없이 적용)

1. **파일 경로 표시**: 보고서를 작성/수정하면 **응답 최하단에 저장 파일 경로를 항상 표시**한다.
2. **독자 적합성(외부·비개발 독자일 때 필수)**: 인사처 등 비개발 독자 대상 보고서는
   - **건수·% 등 핵심 숫자와 결론을 맨 앞에** 둔다(방법론·근거는 뒤로).
   - **모든 수치에 해석 문장**을 붙이고, 내부 용어(티어·CLEAN·극성 등)는 **평문으로 치환하거나 용어 풀이표**를 둔다.
3. **집계값 vs 추정값 구분**: 전수 집계한 정확한 값과, 표본 기반 추정치(오차범위 존재)를 **명확히 구분 고지**한다. 추정치는 범위로 표기(예: `≲0.5%`, `+10~20%`).
4. **근거·재현성**: 수치는 **산출 절차·스크립트·시드·기준을 인용**해 "누가 다시 해도 같은 값"임을 보인다(주관 판단 아님). 표준 절차가 있으면 그 문서를 링크한다.
    - 근거가 소실돼 **재현 불가가 확정된 수치**는 한계로 고지하고 그대로 두는 것이 아니라 **근거에서 제외**한다 — 인용 금지 표기 + 전 인용처 동시 정정([17-hallucination-prevention/09-data-absence.md](17-hallucination-prevention/09-data-absence.md) ABS-9). 표본을 다시 뽑을 수 있는 것만으로는 재현이 아니다(ABS-10).
5. **정직 고지(과장·자축 금지)**: 완료/실패/생략을 있는 그대로, **한계·불확실성**을 명시한다. 유형·목록형 결과엔 필요 시 **"완전한 목록 아님"** 등 범위 한계를 밝힌다.
6. **참조 지침 명시**: 보고서 상단에 참조한 지침 문서 목록을 기재한다([02.documentation](02-documentation.md) §문서 최신성).
7. **이력형은 누적**: 개선/현황 보고서는 **단일 스냅샷을 덮어쓰지 말고 기간대별로 누적**한다(개선 역사 전량 보존).
8. **완료(DN) 보고는 실동작 검증 후**: 단위테스트만으로 완료 선언하지 않는다(실행 검증 전엔 진행/보류로 보고).
9. **산출물 범위 = 요청받은 것 하나**: 요청받지 않은 부속 문서(규격서·지면 예산표·근거대장·개정이력)를 파생시키지 않는다. **규격을 다루는 분량이 본문보다 많아지면 잘못 가고 있는 것**이므로 멈추고 보고한다. 지면이 한 장에 들어가는지는 mm 계산이 아니라 **분량 한도(항목 수·글자 수) + 인쇄 미리보기 1회**로 닫는다.
10. **이력·정정은 본문 밖으로 격리(외부 제출본 필수)**: 본문에는 **확정값만** 둔다. 취소선·「🔴 정정」·「철회」 주석을 본문에 쌓지 않는다 — 구값을 **실제로 교체**하고, 무엇이 왜 바뀌었는지는 **문서 말미 개정 이력 절 1개**([22-doc-numbering.md](22-doc-numbering.md) NUM-9 RV-4)에만 적는다. 정정 대조표가 필요하면 **별도 이력 문서**로 뺀다. §2-7(이력형 누적)은 **내부 이력 문서**에 적용되는 규칙이지, 외부 독자용 본문을 이력 저장소로 쓰라는 뜻이 아니다.
    - 판별 기준: **「이 줄을 지워도 독자가 결과를 이해하는 데 지장이 없는가」** — 지장이 없으면 본문이 아니라 이력이다.
    - **폐기된 판**은 본문 앞머리에 이력을 쌓지 말고 **최상단 3줄 이내 폐기 고지 + 정본 링크**로 끝낸다. 폐기본에 정정 대조표를 유지하는 것은 이력 보존이 아니라 **독자가 폐기본을 계속 읽게 만드는 일**이다.
    - 실사고: 외부 제출 결과보고서에서 정정·개정·폐기 표지가 붙은 줄이 **867줄 중 63줄(7.3%)**, 정본에서 **1,601줄 중 122줄(7.6%)** 로 누적됐고, 폐기 고지·정정 대조표만으로 본문 앞 **46줄**이 소비됐다.
11. **개정분을 본문 뒤에 덧붙이지 않는다**: 개정에서 새로 쓴 절은 **그 내용이 속하는 장 안**에 넣는다. 「N차 개정 신설분」 같은 덩어리를 문서 끝에 붙이면 같은 주제가 두 곳에 흩어져 목차가 결과 구조를 더 이상 반영하지 못한다.
    - **구조를 헤딩 grep 으로 판정할 때는 코드펜스 안을 먼저 배제한다.** 펜스 안의 `#` 주석이 헤딩으로 잡혀 없는 구조 결함을 만들어 낸 오진이 있었다 — 장별 줄 수를 셀 때도 같은 오차가 실린다.
12. **인사이트 우선 구조**: 결과·성과를 보고하는 문서는 [30-report-insight-structure.md](30-report-insight-structure.md) **INS-1~18** 을 함께 지킨다. 세트로 나누면 **고지 도달 검사**(INS-12 — [33-report-set-split.md](33-report-set-split.md) §3)까지 실행한다. **한 절 = 한 인사이트**(제목 아래 첫 줄이 `**라벨**: 설명` 형식의 결론 — INS-11), 요약 표 먼저·상세 근거는 뒤에 번호로 매칭, 순서·분기는 흐름도, 정확값은 최초 1회 뒤 축약 단위. 착수 전 **인사이트 개요표**(30-report-insight-structure.md §2)를 먼저 채운다 — 다 쓴 뒤에 구조를 고치는 것은 실패한다.
13. **결론 줄의 형식과 담을 것**: 결론 줄의 **표기**(문체별 형식·개조식 3단 위계)는 [31-administrative-report-format.md](31-administrative-report-format.md) §1·§1-1 이, 그 줄에 **무엇을 담는가**(도메인 선행·지표 정의 출처·이관 무결성·절 대표값 일치·표/기호 오독 방지·why-first)는 [35-report-claim-integrity.md](35-report-claim-integrity.md) INS-13~18 이 정본이다. 두 문서의 규칙 본문을 이 문서에 옮겨 적지 않는다.

1. §1에서 보고서 종류를 특정 → 해당 정본 지침/템플릿을 연다.
2. §2 공통 규칙을 체크리스트로 적용한다(특히 외부 독자면 2·3항).
3. 결과 보고 문서면 **인사이트 개요표를 먼저 채워 제시**한다([30-report-insight-structure.md](30-report-insight-structure.md) §2). 한 문장으로 못 쓰는 절은 여기서 없앤다.
4. §3 뼈대 + 정본 템플릿 세부로 채운다.
5. 외부 제출본이면 §5 로 **본문에 남길 것과 부록으로 뺄 것을 먼저 가른 뒤** 쓴다.
6. 출고 전 [30-report-insight-structure.md](30-report-insight-structure.md) §7 자가검사를 실행해 결과를 보고에 적고, 완료 후 응답 최하단에 파일 경로를 표시한다(§2-1).

## §5. 외부 제출본의 본문·부록 분리 (발주기관·비개발 독자)

**판별 질문 하나** — 「독자가 **의사결정**을 하는 데 이 절이 필요한가.」 필요하면 본문, 「우리가 제대로 했음을 보이는 것」이면 부록이다. 후자를 본문에 두면 독자는 자기 질문의 답을 찾지 못한다.

| 독자가 묻는 것 | 본문에 두는 것 |
|---|---|
| 무엇이 얼마나 좋아졌나 | 도입 전후 핵심 수치 1개 표 + 해석 문장 |
| 우리 자료에 써도 되나 | 실제 운영 자료 전수 결과 · 적용 범위 |
| 틀리면 어떤 일이 생기나 | 오류 유형과 빈도 · 영향 · 대응 |
| 우리가 지금 무엇을 해야 하나 | 조치 요청 · 확정 필요 사항 · 한계 |

| 부록·별도 문서로 빼는 것 | 이유 |
|---|---|
| 수식·검정 절차·신뢰구간 산식 | 결론에 이미 반영된 계산 과정 |
| 표본 적격성·눈가림 절차·라벨 출처 내역 | 검증 과정의 자기 증명 |
| 단계별 개발 추이 · 모델 학습 경위 · 규칙 엔진 진화 | 개발 이력 |
| 정정 대조표 · 폐기 판 목록 · 개정 이력 | §2-10 |
| 반입 파일명·행수 대조·재추출 경위 | 데이터 취급 이력(요약 1줄만 본문) |

- **분량 상한**: 검증 방법론·개발 이력에 해당하는 분량이 **본문의 30%를 넘으면 구성이 잘못된 것**이다. 실측으로 확인한다(장별 줄 수). 실사고: 정본 1,601줄 중 수식·검정 485줄(30.3%) + 표본 적격성 184줄이 본문에 있었다.
- **한 주제는 한 곳에.** 같은 수치를 여러 장에서 다시 설명하지 않는다. 요약 절을 둘로 쪼개지 않는다(실사고: 「1. 요약」과 「2. 요약」이 따로 있었다).
- 부록을 별도 파일로 뺄 때는 **본문에 한 줄 포인터**를 남기고, 본문·부록 어느 쪽도 같은 값을 두 번 계산해 적지 않는다.

### §5-1. 붙임이란 무엇인가

**붙임은 절이 아니라 문건이다.** 본문이 **다른 문건에서 이미 보고된 값을 인용**할 때, 그 값의 **증명(어디서 나왔나)과 상세보기(어떻게 나왔나)** 를 위해 존재한다. 통합 문서를 만들 때는 각 붙임을 **독립된 주제**로 뒤에 붙인다.

| # | 규칙 |
|---|------|
| ATT-1 | **원본 문건이 있어야 붙임이다.** 본문에서 밀려난 표는 붙임이 아니라 부록·본문 표다. 원본이 없는데 붙임으로 부르지 않는다 |
| ATT-2 | 붙임 첫머리 또는 말미에 **원본 문건명과 판·일자를 밝힌다.** 「이 붙임은 〈원본〉의 무엇을 인용·요약한 것」이라고 쓴다 |
| ATT-3 | **원본이 정본이고 붙임은 사본이다.** 값이 어긋나면 원본을 고치고 붙임이 따라간다. 붙임만 고쳐 원본보다 정확해지는 역전을 만들지 않는다 |
| ATT-4 | 붙임은 **최상위 단위**이므로 **새 쪽에서 시작한다**. 앞 단위 끝에 쪽 나눔을 둔다([27-document-output-standard.md](27-document-output-standard.md) OUT-7·§4) |
| ATT-5 | 붙임 표지의 **표기 형식은 양식 정본이 정한다**([`02-absolute-rules.md`](../operator-manual/DEVELOPMENT/00-a4-authoring-guide/02-absolute-rules.md) §2-4). 표지가 헤딩이 아닐 수 있으므로 **목차·대사에서 별도로 계상**한다 |

> **왜 ATT-3 인가** — 붙임은 원본을 증명하려고 있는데, 붙임이 더 정확하면 증명 관계가 뒤집힌다. 검수자가 붙임 → 원본 순으로 확인하면 그 자리에서 걸린다. 실사고: 제외 내역 분모 설명을 붙임에만 넣고 원본 산출표에는 넣지 않아, 원본에 산술합 49 vs 계 46 의 미설명 불일치가 남았다.
