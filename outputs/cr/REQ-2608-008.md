### 변경 요약 (1줄, 50자 이내)
> 그룹분석 배치 이력 로드 UX 재설계 — 명시적 로드 게이팅 + 상태 통합

### 변경 배경 / 이유
> `/perspective_test`(그룹분석) 화면에서 사용자가 실사용 중 여러 차례 피드백을 준 결과 아래 문제가 확인됨: (1) 배치 이력을 아직 로드하지 않았는데도 페이지 진입 시 `window.onload=loadMeta()`가 조용히 "전체 배치"를 자동 로드해 매트릭스/제출용/그래프 저장 버튼이 동작해버림, (2) 저장 버튼 활성화 로직(`_doBatchTitleCheck()`)이 배치 로드 여부를 전혀 보지 않고 제목 텍스트만 검사, (3) 체크박스 0개 상태로 "선택된 배치 로드"를 눌러도 "전체 배치"로 대체 로드됨, (4) 로드 결과 메시지·안내 문구가 버튼과 먼 곳(`#statusMsg`)에 산발적으로 표시돼 로드 실행 위치와 결과 표시 위치가 분리, (5) 배치 이력 표에 배치별 로드 상태 표시가 없어 어떤 배치가 실제 반영됐는지 알 수 없음.

### 변경 전 → 변경 후
- Before: `window.onload = loadMeta;` — 페이지 진입 즉시 `_selectedBatchIds=[]`("전체 배치")를 조용히 자동 로드. 저장 버튼은 제목 텍스트만 검사해 활성화. 체크 0개+로드 클릭 시 전체 배치로 대체 로드. 로드 결과·안내 문구가 `#statusMsg`/`#batchTitleStatus`/`#graphMetricAllWarning` 3곳에 산발.
- After : `window.onload = function() { _updateBatchLoadBadge(); };` — 자동 데이터 로드 완전 제거(배지 초기화만 수행). 신규 전역 `_batchScopeAppliedOnce` 플래그가 "선택된 배치 로드" 버튼을 실제로 눌러 성공했을 때만 `true`, 체크박스 조합 변경 시 즉시 `false`로 재무효화. `_doBatchTitleCheck()`가 이 플래그를 먼저 검사해 `false`면 저장 버튼 3종을 강제 비활성 + "먼저 배치를 체크하고 [선택된 배치 로드]를 눌러주세요" 안내. `applyBatchScope()`에 체크 0개 가드 추가(로드 자체를 막고 경고만 표시, 전체 배치 대체 폐기). 배치 이력 표에 "상태"(로드됨/로드 필요) 열 신설(`_updateBatchRowStatuses()`), 로드 결과 메시지는 `batchLoadBadge`(로드 버튼 바로 옆)로 이동. 행 클릭(체크박스·버튼 제외 영역)으로도 체크박스 토글 가능(`_toggleBatchRow()`). 안내/상태 문구 3계열을 `#statusMsg` 한 줄로 최종 통합.

### 영향 범위
> `/perspective_test`(그룹분석) 화면 단일 페이지. 서버측 API·라우트·다른 화면에는 영향 없음(클라이언트 JS/HTML/CSS만 변경). 세션 복원(`_restorePageState()`)은 `loadMeta()` 내부 가드에 남아있어 트리거 시점이 "페이지 진입"에서 "첫 명시적 로드 클릭"으로 자연히 이동(코드 변경 없이 부수 효과).

### 공지용 요약

**[상세 내용]**
> 그룹분석(`/perspective_test`) 화면에서 배치 이력을 명시적으로 로드하기 전에는 매트릭스/제출용/그래프 저장이 동작하지 않도록 게이팅을 도입했다. 페이지 진입 시 조용히 이뤄지던 "전체 배치" 자동 로드를 완전히 제거하고, 체크박스로 배치를 고른 뒤 "선택된 배치 로드" 버튼을 눌러야만 실제 데이터가 반영된다. 배치 이력 표에는 배치별 "로드됨/로드 필요" 상태 열이 추가됐고, 로드 결과 메시지는 로드 버튼 바로 옆에 표시된다. 안내 문구는 한 줄로 통합해 카드 레이아웃이 흔들리지 않도록 했고, 표의 행은 어디를 클릭해도 체크박스가 토글된다.

**[요약]**
> 그룹분석 화면의 배치 로드를 명시적 동작으로 바꾸고, 배치별 로드 상태 표시와 메시지 위치를 정리했다.
