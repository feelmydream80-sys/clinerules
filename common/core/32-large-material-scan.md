# 32. 대용량 자료 사전 규모 측정 (LMS)

> **적용 대상 — 분석·작성 작업의 근거 자료가 대용량일 수 있는 모든 경우**(긴 문서, 다수 소스 파일, 다수 이미지, PDF 등). 서브에이전트는 [28-agent-bootstrap.md](28-agent-bootstrap.md) BOOT-7 에서 이 문서를 수행한다. 메인 세션도 동일 원칙을 따른다.
>
> **막으려는 실패** — 근거 자료의 규모를 가늠하지 않고 대용량 문서·다수 소스 파일·다량 이미지를 한 번의 도구 호출로 통째로 읽으려다 장시간 응답 없이 실행이 멈추고, 산출물 없이 시간만 소요된 사례가 있었다.

---

## 1. 규칙 — LMS

| 조항 | 내용 |
|------|------|
| LMS-1 | **측정이 먼저다.** 대용량일 수 있는 자료를 근거로 분석·작성에 착수하기 **직전**, 전체를 읽기 전에 규모부터 측정한다. 규모를 모른 채 곧바로 전체를 한 번의 도구 호출로 읽지 않는다 |
| LMS-2 | 측정한 규모가 §2 임계치를 넘으면 §2 의 분할 방법으로 나눠 처리한다. 임계치는 절대 기준이 아니라 **가늠 기준**이다 — 애매하면 나눠 처리하는 쪽을 택한다 |
| LMS-3 | **한 도구 호출·한 턴에 거대 자료 전체 또는 다량의 파일·이미지를 한꺼번에 밀어넣지 않는다.** 이것이 이 문서의 핵심 금지다 |
| LMS-4 | 측정값과 채택한 분할 전략을 보고에 남긴다 — "규모 확인 없이 진행"과 "확인했고 임계 이하라 통짜로 읽음"은 결과가 같아도 근거가 다르다 |

## 2. 자료 유형별 측정·분할

| 자료 유형 | 측정 방법 | 가늠 기준(예시) | 초과 시 분할 방법 |
|---|---|---|---|
| 텍스트·마크다운 문서 | 줄 수(`wc -l` 또는 Read 결과 헤더) | 수백 줄 이상 | Grep 으로 필요한 절만 먼저 찾고, Read `offset`/`limit` 으로 그 구간만 읽는다 |
| 코드베이스(다수 소스 파일) | Glob 결과 파일 개수 | 여러 파일(한 자리 수 후반) 이상 | 디렉터리 단위로 나눠 Glob → 하위 그룹별로 순차 처리한다 |
| PDF | 페이지 수 | 10페이지 이상 (Read 도구 자체가 20페이지/요청 상한을 둔다) | `pages` 파라미터로 구간을 나눠 요청한다 |
| 이미지 자료(슬라이드 등) | 파일 개수(Glob) | 여러 장 이상 | 필요한 이미지만 선별해 열고, 전량을 한 턴에 열지 않는다 |

측정 자체가 크면(예: 파일이 매우 많은 디렉터리) 측정 방법도 나눠서 수행한다 — Glob 을 하위 폴더별로 나눠 부르는 식.

- [28-agent-bootstrap.md](28-agent-bootstrap.md) BOOT-5(구조 추측 금지, Glob·Grep 으로 실측)와 같은 원리다 — 재보지 않고 크기를 가정하면 그 가정이 틀렸을 때 대응할 수 없다.

## 4. 검사

BOOT 절차와 같이 실행 시점 행동이라 정적 린트 대상이 아니다. 측정값·분할 전략이 보고(LMS-4)에 있는지는 사람이 확인한다.
