# 실제 사례 기반 교훈

> 대화에서 도출한 교훈. 지속 추가.

- "안 돼요", "작동 안 해요", "에러나요" → 기존 기능 디버깅 우선, 새 기능 구현 금지
- "기능 라이브러리 로드 실패" 에러 발생 시: API 엔드포인트, 모델 필드, 호출 경로 먼저 확인
- **"정렬/필터링/데이터 표시" 문제: SQL 단에서만 멈추지 말고 전체 파이프라인(백엔드→정제→정렬→프론트엔드)을 검증할 것. docs/verification/pipeline-analysis.md 참조**
- **사용자가 문제 위치를 특정해줬으면: 그 위치를 먼저 확인하고, 사용자가 지시한 분석 순서를 따를 것. 성급한 결론 금지**
- **사용자가 "아니다", "잘못됐다"고 하면: 즉시 중단하고 "어떤 부분이 잘못되었는지" 확인할 것. 동일한 실수를 반복하지 말 것**
- **주석/로그 제거 작업 시**: [14.comment-log-removal.md](../14.comment-log-removal.md) 참조 (제외 디렉토리 필수 확인)
- **사용자의 원인 가설은 검증 대상이다**: "너비 부족" 같은 추정은 사실이 아니다. DOM·ComputedStyle·스크린샷으로 실제 렌더링을 확인한 뒤 수정에 착수할 것. `05.testing.md` 시각 검증 의무 참조
- **CSS Grid/Flex overflow 함정 (2026-08 드롭 테이블 사례)**: `1fr` = `minmax(auto,1fr)` → 내용 최소폭이 열폭을 밀어내 overflow/겹침 발생. 해결: 열 정의에 `minmax(0,1fr)` 사용 또는 셀에 `min-w-0` / 행에 `[&>*]:min-w-0` 부여. `Input` 등 기본 `min-width:auto` 요소가 포함된 그리드는 항상 확인
