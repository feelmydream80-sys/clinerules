# 34. 사내 제출 서식 정본 (FORM)

> 최종 개정 2026-08-25 (당일 제2차) — rev-260825-02
>
> **적용 대상 — 사내 결재·상급 보고로 올리는 제출 서식 문서**(구축 완료 보고 1장 · FP 종합 분석표). 서식은 **사용자가 실제로 제출한 판**이 정본이고 우리가 바꾸지 않는다.
>
> [31-administrative-report-format.md](31-administrative-report-format.md) 가 **무엇을 쓸지**(결론 형식·본문 존치)를 정한다면, 이 문서는 **어떤 모양으로 낼지**(서식 요소·절 이름·표 컬럼)를 정한다. 내용 규칙은 [16-report-writing.md](16-report-writing.md), 인쇄 규격은 [27-document-output-standard.md](27-document-output-standard.md).

**이 규격이 막으려는 실패**: 내용은 맞는데 **제출처가 받아 본 적 없는 모양**으로 나오는 문서. 실사고 — 직전 판 md(79행·6블록·유의사항 각주)를 저본으로 삼아 원페이퍼를 썼는데 실제 제출본은 5블록·개조식·A4 1장이어서 구성·기간·항목명이 전부 달라 산출물을 폐기했다.

---

## 1. 서식 요소 (FORM-1~5) — 두 문서 공통

| 조항 | 요소 | 규칙 |
|------|------|------|
| **FORM-1** | 제목 | 문서 최상단 **테두리·음영 박스 안 굵은 고딕 1줄**. 부제·날짜·판번호를 제목 줄에 붙이지 않는다 |
| **FORM-2** | 작성자 | 제목 **바로 아래 우측 정렬 1줄** — `<처> <부> <직급> <이름>(☏ <내선>)`. 소속·연락처는 이 줄 외에 적지 않는다 |
| **FORM-3** | 절 제목 | 번호 + 제목. 번호 표기(`1.` 또는 역상 숫자 박스)는 **한 문서 안에서 하나로 통일** |
| **FORM-4** | 개조식 위계 | `□`(1단) → `○`(2단) → 표. **3단을 만들지 않는다.** 문단형 서술 금지 |
| **FORM-5** | 표 | 머리 행 **음영 + 굵게**, 본문 셀 **가운데 정렬**(비고·근거 열만 왼쪽), **합계 행 굵게** |

**문말은 명사형으로 끝낸다** — `~필요`·`~완료`·`~정립`·`~단축`·`~추가`. 서술 종결(`~합니다`·`~했다`)을 쓰지 않는다. 이는 [31](31-administrative-report-format.md) §1 문체 표가 개조식 문서 전체에 정한 명사형 종결의 **적용**이며(예외가 아니다), 이 두 문서 유형에서 쓰는 **체언 종결의 세부 형태**는 여기가 정본이다.

**라벨 없는 `□` 은 절 도입부의 배경 진술 1줄에만 허용**한다 — 31 §1 「라벨 없는 `□ <설명>` 은 위반」의 유일한 예외다. 결과·성과·계획을 담는 줄은 예외 없이 `□ (<라벨>) <설명>` 이다.

## 2. 구축 완료 보고 — 절 골격 (FORM-6)

**A4 세로 1장 · 5개 절 · 이미지 없음.** 절을 늘리지 않는다.

| 절 | 이름 | 담는 것 | 분량 |
|----|------|---------|------|
| 1 | **사업 개요** | 표 1개(3열 × 2행) — 기간 · 규모 · 비용. 열마다 값 2줄(요약값 / 부연값) | 표 1개 |
| 2 | **추진배경 및 추진 결과** | 라벨 없는 배경 `□` 1줄 + **AS-IS / TO-BE 3열 대비표** | 1줄 + 표 1개 |
| 3 | **구축 성과** | `□ (<분류>) <이전> → <이후> 완료` | 3줄 |
| 4 | **기대 효과** | `□ (정성적) …` · `□ (정량적) …` | 2줄 |
| 5 | **향후 계획** | `□ (<과제명>) <할 일>` | 2줄 |

- 「핵심 구축 내용」·「대표 화면」은 **이 서식의 절이 아니다.** 구축 내용은 3절 성과 줄에 흡수한다.
- 항목 1줄은 **40자 이내**. 넘치면 지면을 계산하지 말고 **항목을 지운다**([16](16-report-writing.md) §2-9).
- 2절 대비표는 이 서식에서 **가장 눈에 띄는 자리**다. 행은 업무 구분 단위로 4행 안팎.

## 3. FP 종합 분석표 — 절 골격 (FORM-7)

**A4 · 7개 절.** 절이 끝나면 쪽을 나눈다(OUT-7).

| 절 | 이름 | 담는 것 |
|----|------|---------|
| 1 | **산정 개요** | `□ 개요`(대상 시스템·평가 유형·산정 방식·산정 범위(기능)·산정 범위(데이터)·애플리케이션 경계) · `□ 유형별 기능 점수` · `□ FP당 단가` |
| 2 | **산정결과** | `□ <총 FP> FP 산정` · `□ 개발비` · `□ 기능산정 총괄(제외 총 N건)` |
| 3 | **트랜잭션 기능 산정 내역** | 기능 그룹별 `□` + 표 |
| 4 | **데이터 기능 산정 내역** | `□ 내부논리 파일`(ILF) · `□ 외부 인터페이스 파일`(EIF) |
| 5 | **보정계수 및 개발비** | `□ 보정 계수`(요인 · 내용 · 계수, 총합 행에 곱셈식 그대로) · `□ 개발원가 산출`(단계별) |
| 6 | **산정 총괄** | `□ 기능 총괄`(산정 / 제외 / 계) · `□ 기능 유형별 총괄` |
| 7 | **산정 제외 내역(N건)** | 유형별 요약표 1개 + **유형마다 상세표 1개**(무엇을 왜 뺐는지) |

**3·4절 각 표의 바로 위 우측**에 인라인 요약을 둔다 — `EI 12   EQ 3   FP 59.7` (그 표에 등장하는 유형만, 0 은 적지 않는다).

**표 컬럼은 고정이다.**

| 표 | 컬럼 |
|----|------|
| 트랜잭션 산정 내역(3절) | `NO │ 대분류 │ 소분류 │ 유형 │ 비고 (인정 근거)` |
| 데이터 산정 내역(4절) | `NO │ 대분류 │ 소분류 │ 물리 │ 비고 (인정 근거)` |

- **비고는 업무 언어 한 줄**이다 — `ILF(<테이블>) 갱신` · `단순 조회` · `파생데이터 생성` · `조건만 상이`. 검증 행위(`grep 0건`·`소스 전수 검색`)·`<파일>:<라인>`·AI 판단·잔여 리스크는 **내부검토의견 문서에만** 쓴다.
- 3·4절 인라인 요약의 합 = 2절·6절 총괄 = 7절 제외 건수의 여집합. **세 자리가 어긋나면 산정이 끝나지 않은 것**이다(정합성 대사).

## 4. 자가검사

```sh
grep -cE '^[[:space:]]*□ [^(]' <파일>          # 라벨 없는 □ — 절당 1줄(배경)만 허용
grep -nE '(합니다|했다|하였다|되었다)\.?$' <파일>   # 문말 위반 — 0 이어야 한다
grep -cE '^[[:space:]]*[-*] '  <파일>           # 마크다운 불릿 — 0 (개조식 기호만 쓴다, FORM-4)
```

**저본(사용자가 실제 제출한 판)이 이 문서를 이긴다.** 저본과 다르게 쓸 이유가 생기면 임의로 바꾸지 말고 **근거와 함께 보고**해 사용자가 판단하게 한다.
