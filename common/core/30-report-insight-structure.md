# 30. 인사이트 우선 구조 · 표현 규격 (INS)

> 최종 개정 2026-08-25 (당일 제4차) — rev-260825-04
>
> **적용 대상 — 결과·성과를 사람에게 보고하는 모든 문서**(결과보고서·상세보고서·감사보고서·현황보고). **대상이 아닌 것** — 내부 메모·계획서, 그리고 **절차를 안내하는 문서**(운영자 메뉴얼·사용 설명서·작업 절차서). 절차서의 절은 「무엇을 알게 되는가」가 아니라 「무엇을 하는가」로 열리는 것이 옳다. **절차서에 INS 위반을 세지 않는다** — 전건 위반이 나올 뿐이다. 행정 서식 문서는 [31-administrative-report-format.md](31-administrative-report-format.md), 주장 무결성(INS-13~18)의 판정 예·실사고·검사는 [35-report-claim-integrity.md](35-report-claim-integrity.md), **보고 서술 기법(T-1~T-13)·표 설계 규범(TB-1~TB-14)** 은 [36-report-craft-canon.md](36-report-craft-canon.md).
>
> [16-report-writing.md](16-report-writing.md) §2(공통 규칙)·§5(본문·부록 분리)와 함께 적용된다. §5 가 **무엇을 본문에 둘지**를 정한다면, 이 문서는 **본문에 둔 것을 어떻게 배치·표현할지**를 정한다.

**이 규격이 막으려는 실패**: 내용은 다 맞는데 독자가 읽고도 **무엇을 알게 됐는지 말할 수 없는 문서**. 실사고 — 단일 결과보고서 1,645줄, 절 60여 개가 전부 「무엇을 측정했다」로만 끝나 상급자가 절마다 스스로 해석해야 했다. 수치 오류는 0건이었으나 보고서로는 실패였다.

## 1. 규칙 — INS

| 조항 | 내용 | 검사 |
|------|------|------|
| INS-1 | **한 절 = 한 인사이트.** 절 제목은 **명사구**로 쓰고(INS-10), 제목 바로 아래 첫 줄에 **결론 문장**을 둔다. 표·수치·정의로 시작하는 절을 두지 않는다 | 수동(§2) |
| INS-2 | **요약 먼저, 근거 뒤.** 절은 `결론 1~2줄 → 요약 표 1개 → 상세 근거` 순이며, 요약 표의 각 행과 상세 항목을 **같은 번호로 매칭**한다. 상세를 건너뛰어도 결론이 성립해야 한다 | 수동 |
| INS-3 | **글 대신 표·그림.** 6줄 넘는 산문 문단을 두지 않는다. 3항목 이상의 비교·절차·분기는 표 또는 **흐름도**로 그린다 | 수동(§3) |
| INS-4 | **한 칸 = 한 사실.** 표 한 칸에 사유·경위·수치·상태를 몰아넣지 않는다. 한 칸이 두 문장을 넘으면 열을 쪼개거나 상세로 내린다 | 수동 |
| INS-5 | **수량은 끊어 쓴다.** 정확값은 **최초 1회만** 적고(`1,234,567건(약 123만)`) 이후 전부 축약 단위(만·백만)로 쓴다. 표의 계산 열은 정확값을 유지하되 열 머리에 단위를 명시한다 | 수동(§4) |
| INS-6 | **설명은 대상부터.** 값을 쓰기 전에 **무엇에 대한 값인가**(대상·단위·분모)를 밝히고, 그다음 해석 1줄을 붙인다 | 수동 |
| INS-7 | **지표는 용도와 함께.** 지표·측정 체계를 정의만 하고 끝내지 않는다. **독자가 그 값으로 무엇을 판단하는지**를 함께 적는다. 판단 용도를 한 줄로 못 적는 지표는 본문에서 뺀다 | 수동 |
| INS-8 | **결과 문서에 이력·한계·조치요청을 섞지 않는다.** 별도 문서로 빼고 본문에는 포인터 1줄만 남긴다(§2-10 의 확장). **단, 본문이 근거로 쓴 수치의 결격 사유(재현 불가·철회·적용 범위 밖)는 빼지 않는다 — 그 수치와 같은 자리에 둔다(INS-12).** **단일 문건으로 제출하는 문서는 [31](31-administrative-report-format.md) §2 예외를 적용한다** | 수동(§5) |
| INS-9 | **규모가 커지면 주제별로 쪼갠다.** 단일 결과보고서가 분할 임계를 넘으면 주제별 문서 세트 + **안내서 1장**으로 재구성한다 | 수동([33](33-report-set-split.md) §1·§2) |
| INS-10 | **절제된 보고서 문어체.** 절 제목·단락명·표 머리는 **명사구**로 쓴다. 본문에 수사·비유·설득조·독자 호출을 쓰지 않고, 비유로 만든 도메인어(「시험지」·「눈금」)를 **업무 용어**로 바꾼다. 금지 표현 사전 → §2 | 수동(§2·§7-7) |
| INS-11 | **절은 결론 문장으로 시작한다.** 기본 형식은 `**<라벨>**: <설명>`, **행정 개조식 문서는 [31](31-administrative-report-format.md) §1 이 정한 개조식 형식(`□ (<라벨>) <설명>` · `○ **<도메인>**: <설명>`)을 동등 형식으로 인정한다** — 문체별 적용 대상과 위계 상한은 31 §1·§1-1 이 정본이다. 라벨 = 그 절이 확정하는 **대상의 명사구**(문장이 아니다 — §2-2 사전을 라벨에도 적용). 설명 = **한 줄·한 문장**. 종결은 **문체가 정한다 — [31](31-administrative-report-format.md) §1 문말 표가 정본**이다(개조식 문서는 명사형). 배경·전제·안내문은 이 줄에 넣지 않고 **다음 줄로 내린다** | 수동(§2-1)·§7-8 |
| INS-12 | **고지는 도달해야 유효하다.** 문서를 세트로 나누면 각 한계·제약 고지가 **어느 독자 경로에 도달하는지 표로 확인**한다. 「이 문서 하나로 판단이 된다」고 안내한 문서에는 **그 판단에 영향을 주는 한계가 전부** 실려 있어야 하고, 수치를 근거로 제시하는 자리에는 그 수치의 **결격 사유를 같은 자리에** 둔다(다른 문서 링크로 대체 불가) | 수동([33](33-report-set-split.md) §3) |
| INS-13 | **도메인 선행.** 결론 문장은 판단 대상 영역(데이터·평가·운용·측정 등)을 **먼저** 밝히고 설명을 뒤에 둔다. 도메인 없이 결론만 단문으로 나열하지 않는다 | 수동([35](35-report-claim-integrity.md) §1) |
| INS-14 | **지표 정의는 출처에서 온다.** 지표의 정의·기준선·임계는 **코드 또는 원자료에서만** 가져온다. 문서화되지 않은 기준을 집필자가 만들어 넣지 않으며, 없으면 「정의 없음」으로 보고한다 | 수동([35](35-report-claim-integrity.md) §2) |
| INS-15 | **이관 무결성.** 수치를 다른 절·문서로 옮길 때 **원본의 해석 문장을 함께** 옮긴다. 숫자만 남으면 도메인 없는 문장이 된다 | 수동([35](35-report-claim-integrity.md) §3) |
| INS-16 | **절 결론 = 채택 대표값.** 절의 결론 문장이 내세우는 값은 그 절이 대표로 채택한 값과 같아야 한다. 어긋나면 결론이 아니라 **근거표의 판정부터** 고친다 | 수동([35](35-report-claim-integrity.md) §4) |
| INS-17 | **표·기호의 오독 방지.** 포함 관계의 모집단(부분집합·전체집합)을 한 표의 같은 열에 세로로 쌓지 않는다 — **오독 방지 각주를 달아야 한다면 표 구성이 틀린 것**이므로 재구성한다. 한 문서에서 `①②③④` 를 인접 절마다 다른 대상에 재사용하지 않는다 | 수동([35](35-report-claim-integrity.md) §5) |
| INS-18 | **why-first — 성과는 대응 문제를 되짚는다.** 성과·효과를 적는 문서는 그 성과가 해소한 문제를 같은 문서에서 밝히고, 문제 항목과 성과 항목이 **개수·순서로 대응**해야 한다 | 수동([35](35-report-claim-integrity.md) §6) |

## 2. 인사이트 개요표 (INS-1 — 착수 전 1회, 다 쓴 뒤에는 고칠 수 없다)

**절을 먼저 만들고 인사이트를 끼워 맞추지 않는다.** 쓰기 전에 이 표를 채우고, 채운 표를 사용자에게 보인 뒤 본문을 쓴다.

| 절 | 이 절을 읽고 독자가 알게 되는 것(한 문장) | 그 근거가 되는 표·그림 |
|----|--------------------------------------|--------------------|

- **한 문장으로 못 쓰는 절은 쓰지 않는다**(통합하거나 부록으로 내린다). 같은 문장이 두 절에 오면 **그 두 절은 한 절이다.**

### 2-1. 제목은 명사구, 인사이트는 제목 아래 첫 줄이 진다 (INS-1 + INS-10 + INS-11)

**개요표의 「알게 되는 것」은 제목이 아니라 본문 첫 줄로 들어간다.** 제목에 문장을 넣으면 보고서가 연설문이 된다.

| 절 제목 | 제목 아래 첫 줄(결론 문장 — INS-11 형식) | 판정 |
|---|---|---|
| `검증셋 N건 유형별 결과` | (없음) | ✗ 독자가 무엇을 알게 되는지 없다 |
| `가장 어려운 유형에서도 치명 오류는 나오지 않았다` | (제목이 겸함) | ✗ 제목이 서술문이다 — 인사이트는 맞으나 보고서 제목이 아니다 |
| **`위험 오류 해소`** | `**칭찬↔불만 뒤바뀜**: 검증 자료 4종 761건 전부에서 0건` | ✅ |
| **`표본 규모별 일관성`** | `**측정 규모 간 방향 일치**: 400건 측정과 265만 건 측정이 같은 방향을 가리킴` | ✅ |

- 「~ 결과」·「~ 현황」·「~별」 **단독**은 그대로 금지다. **대상을 한정한 명사구**로 바꾼다(`규모별 종합` → `표본 규모별 일관성`).
- 인사이트를 제목에서 **지우는 것이 아니라 한 줄 아래로 내리는 것**이다. 제목에서 문장을 뺐는데 첫 줄이 결론 문장이 아니면 INS-1 위반이고, 결론 문장이 있어도 라벨이 없으면 INS-11 위반이다.

**형식 대조 (INS-11)** — 실사고: 대외 제출 기술 검토서 §1「측정 체계별 용도」 첫 줄.

| 판정 | 실제 문장 |
|---|---|
| ✗ 서술형 산문 | `**수치가 여러 개인 것은 측정 체계가 여러 개이기 때문이며, 서로 대신하지 못한다.** 측정마다 **판단 가능한 범위**를 아래에 고정한다.` |
| ✓ 라벨 + 설명 | `**판단 한계선**: 각 측정 방식별로 독립적인 판단 가능 범위가 고정되어 있음` |

- ✗ 의 결함 셋 — ⑴ 강조된 것이 라벨이 아니라 **문장**이다 ⑵ **두 문장**이다 ⑶ 뒷문장은 결론이 아니라 **안내문**이다. 안내문이 필요하면 라벨 줄 **다음 줄**로 내린다.

### 2-2. 금지 표현 사전 (INS-10 — 실사고에서 나온 것만 싣는다)

| 유형 | ✗ | ✓ |
|---|---|---|
| 서술형 절 제목 | `가장 위험한 오류가 사라졌다` | `위험 오류 해소` |
| 수사·비유 문장 | 「열에 여덟을 맞히던 것이 백에 아흔여덟이 되었다」 | 「정확도 82.4% → 97.7%」 |
| 비유로 만든 도메인어 | 시험지 · 눈금 · 가장 약한 고리 | 검증 자료 · 측정 체계 · 최대 취약점 |
| 설득조·다짐형 문말 | 「감추지 않고 적는다」 · 「못 박는다」 · 「아슬아슬하게」 | 「기재한다」 · 「고정한다」 · (삭제) |
| 대화체 표 머리 | `알고 싶은 것` · `답하는 질문` · `하지 말 것` | `확인 사항` · `금지 표현` |
| 독자 호출 | 「읽어야 할 한 가지」 · 「반드시 함께 읽을 것」 | 「정리」 · 「함께 확인할 것」 |

> **적용 제외 2곳** — ⑴ 개정 이력·정정 대장의 **인용문**(「변경 전」 문구를 고치면 이력이 무의미해진다) ⑵ **기록 보존본**으로 전환된 구본. 일괄 치환 시 이 둘을 범위에서 뺀다.

## 3. 흐름도를 쓰는 자리 (INS-3)

**표는 「같은 종류의 항목을 나란히」 보일 때 쓰고, 흐름도는 「순서·분기·선택」을 보일 때 쓴다.** 순서가 있는 것을 표에 넣으면 독자가 순서를 스스로 복원해야 한다.

| 내용의 성격 | 표현 |
|---|---|
| 단계 목표 → 수행 내용 → 결과 | **흐름도**(단계를 줄기로, 수행·결과를 가지로 친다) |
| 선택지 A/B 중 무엇을 왜 골랐나 | **흐름도**(후보 → 판정 근거 → 채택/기각) |
| 값의 크기 비교 | 표 또는 도표 |
| 정의·용어 | 표 |

- 흐름도는 이미지 자산으로 만들고 표준 이미지 표기로 삽입한다 — 규격·대사는 [27-document-output-standard.md](27-document-output-standard.md) OUT-4·OUT-5.
- 그림 안 텍스트도 본문이다. 수치가 바뀌면 **이미지 내부 텍스트까지** 함께 고친다.

## 4. 수량 표기 (INS-5)

| 상황 | 표기 |
|---|---|
| 문서에서 그 값이 처음 나올 때 | `1,234,567건(약 123만)` |
| 이후 본문 전부 | `123만 건` |
| 표의 계산·검산 열 | 정확값 유지 + 열 머리에 단위(`건`, `천 건`) 명시 |
| 비율 | 소수 자릿수를 문서 전체에서 하나로 통일 |

- 검사: 정확값 문자열을 전문 grep 해 **본문 등장 2회 이상이면 위반**이다(표 계산 열 제외). 축약해서 결론이 달라지는 자리(경계값·합계 검산)는 축약하지 않고, 축약하지 않은 이유를 각주 없이 그 줄에서 밝힌다.

## 5. 결과 문서에서 빼는 것 (INS-8)

| 빼는 것 | 어디로 |
|---|---|
| 개정 이력·정정 대조·폐기 판 목록 | 별도 이력 문서 ([22-doc-numbering.md](22-doc-numbering.md) NUM-9 RV-4 는 **그 문서 안 1개 절**로 충족한다 — 본문 곳곳의 날짜 딱지를 남기라는 뜻이 아니다) |
| 한계·미측정·해소 경로 없음 | 별도 한계 문서. **단, 본문이 근거로 제시한 수치의 결격 사유는 여기서 빼지 않는다** — 그 수치 옆에 남긴다(INS-12). 링크·포인터로 대체하면 독자는 링크를 따라가지 않은 채 수치를 인용한다 |
| 조치 요청·확정 필요 사항 | 별도 요청 문서(결정권자가 결재하는 단위) |
| 검증 절차·수식·표본 적격성 | 기술 문서 |

판별 질문은 하나다 — **「이 줄을 지워도 독자가 결과를 이해하는 데 지장이 없는가.」** 지장이 없으면 결과 문서의 줄이 아니다. 결격 사유는 지우면 독자가 **틀린 결론**을 얻으므로 언제나 본문이다.

> **예외** — 파일 하나로 제출하는 행정 문서는 한계·향후계획을 본문 말미에 존치한다([31-administrative-report-format.md](31-administrative-report-format.md) §2). 개정 이력은 예외가 아니다.
